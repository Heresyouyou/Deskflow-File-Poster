# 01 · 架构

## 问题定义

一台 Mac 在桌面上，右边是 iPhone。人希望鼠标一路向右移出屏幕边缘，光标就出现在 iPhone 上，键盘输入同时生效——就好像 iPhone 是接在右侧的第二块显示器。

难点不在「控制 iPhone」，而在「**越界**」：macOS 不允许光标离开所有显示器的并集，所以必须存在一块真实的、位于主屏右侧的显示器，光标才「有地方可去」。这就决定了架构的第一块基石是**虚拟屏**，而不是某种软件层面的边缘检测。

## 四层

```
┌──────────────────────────────────────────────────────────┐
│ L4 注入    BLE HID（HOGP）→ iPhone 识别为真实蓝牙键鼠       │
├──────────────────────────────────────────────────────────┤
│ L3 窗口    把 iPhone Use 的画面窗口钉在虚拟屏上（AX）       │
├──────────────────────────────────────────────────────────┤
│ L2 虚拟屏  CGVirtualDisplay 造 509×905 的屏，贴主屏右侧     │
├──────────────────────────────────────────────────────────┤
│ L1 采集    iPhone Use 通过 USB 拿到 H264 画面并解码显示      │
└──────────────────────────────────────────────────────────┘
```

层与层之间只有两种耦合：**几何**（L2 决定 L3 的坐标）和**坐标**（L3 决定 L4 收到的事件该投到 iPhone 的哪个像素）。

## 事件流

```
鼠标物理移动
   │
   ├─ Deskflow 在线？── 是 → Deskflow 判断是否跨机，跨机则拦截
   │                    否 ↓
   ↓
WindowServer 移动光标
   │
   ├─ 光标仍在主屏 → 常规操作，本程序不介入
   │
   └─ 光标越过 x=1680 → 进入虚拟屏
          │
          ├─ L3：窗口已在 (1680,97)，手机画面区 = (1680,125) 393×852
          ├─ 本程序把系统光标隐藏（否则会有两个指针）
          └─ iPhone Use 把光标位移换算成 HID 报文 → 蓝牙 → iPhone 显示指针
```

## 控制面

本程序不直接跟 iPhone 讲话，所有动作都通过 iPhone Use 的本地 HTTP 接口（`127.0.0.1:7390`）转发，见 `protocol/iphone-use-http.md`。好处是 iPhone Use 升级时只要接口不变，这边不用改。

## 三个关键约束

### 1. 几何必须闭环

光标能落到虚拟屏，前提是窗口**真的**在那个位置。AX 设置窗口位置会被系统钳制（`visibleFrame` 会扣掉 25px 菜单栏），所以代码里不能"设完就信"，必须回读校验：

```
place → 回读 frame → 不一致则再设一次 → 仍不一致则本轮判定失败
```

早期版本在这里踩过坑：目标 y 写 72、实际被钳到 97，于是每 4 秒判定"没就位"重摆一次，日志里满是 `place want=... got=...`。

### 2. 光标隐藏要成对

隐藏了必须能恢复。程序被杀、崩溃、屏被撤掉，都要还原光标，否则用户会看到一个"没有鼠标"的桌面。所以：

- `SIGTERM` / `SIGINT` 有 handler，退出前 `CGDisplayShowCursor`；
- 每轮循环都检查"还在不在手机区"，不在就立刻恢复，不依赖退出路径。

### 3. 不能抢焦点

这是本项目最容易踩的产品坑，与架构无关但与体验强相关。

AX 读取窗口列表要求 App 处于激活状态（非激活时 `AXWindows` 返回 count=0）。于是"摆窗口"天然需要激活 App——而激活就意味着**把用户的键盘焦点抢走**。如果摆放失败还循环重试，用户就会遇到"键盘一直被打断"。

现方案：

| 时机 | 行为 |
|---|---|
| 启动时摆放窗口 | 允许激活，**预算 4 次** |
| 摆放成功后 | 立刻把焦点还给原前台 App |
| 指针进入手机区 | **不切换焦点**（要切换需显式加 `--follow`） |
| 摆放失败重试 | 只重试不激活，绝不反复抢焦点 |

## 状态机

守护进程的主循环只有一个状态变量——App 在不在：

```
           ┌──────────── App 未运行 ────────────┐
           │  销毁虚拟屏 / 恢复光标 / 500ms 轮询  │
           └───────────────┬───────────────────┘
                           │ 检测到 iPhone Use 启动
                           ↓
           ┌──────────── App 已运行 ────────────┐
           │ 确保虚拟屏 → 纠回内置屏 → 摆窗口     │
           │ 每 1s 守内置屏分辨率                │
           │ 每 4s 复核窗口位置                  │
           │ 每 16ms 判定光标是否在手机区          │
           └───────────────┬───────────────────┘
                           │ App 退出 / 崩溃
                           ↓
                     回到「未运行」
```

App 退出的判定不走 `NSWorkspace`（它依赖主 RunLoop 的通知，裸 `while(1)` 里拿到的永远是启动瞬间的快照），改用 `libproc` 的 `proc_listallpids` + `proc_pidpath` 直接枚举进程。
