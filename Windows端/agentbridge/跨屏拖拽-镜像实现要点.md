# Windows 镜像实现要点（Mac → Windows 落点投递）

Mac 侧链路已在真机跑通（本仓 `mac/`）。本篇是把**同一套协议**落到 Windows 上的要点：
让 Windows 当**目标端**，接住 Mac 拖过来的文件，落在 Mac 松手的位置。

信令方向与 Mac 作目标端时**完全对称**（只是 source/目标互换）：

```
Mac(源)   drag_<id>_begin.json  ──直推──▶  Windows 8900   （Windows 据此 arm，TTL 30s）
Mac(源)   载荷 file_*/xfer_*    ──直推──▶  Windows 8900   （预传，进 dragstage 暂存区）
Mac(源)   drag_<id>_drop.json   ──直推──▶  Windows 8900   （松手瞬间；Window 收到后立刻读本机光标）
Windows(目标) drag_<id>_sync.json ─直推──▶ Mac 8899        （phase/landed/target 回执）
Mac(源)   drag_<id>_cancel.json ──直推──▶  Windows 8900   （取消/TTL）
```

沿用已冻结的两条规则，不要新起端口：
- 接收侧 `is_payload()` 白名单加 `drag_`（与 Mac 侧同一处判断，两端同源）。
- 入站 `drag_*` 由 `ingest.ingest_entry` 受理后写 spool（Mac 写 `~/AgentBridge/.drag_inbox.jsonl`，
  Windows 写自己的 spool），由目标端控制器增量读取；**未 armed 收到任何 `drag_*` 只记日志不报错**。

## 目标端投递：对应的四步

### 步骤 1 · 落点识别（对应 Mac 的 `dropat.js`）

Mac 用 `CGWindowListCopyWindowInfo`（不依赖 App 配合）。Windows 侧对应物是 **Win32 命中测试**，
本来就不依赖 App 响应，直接可用：

```cpp
POINT pt; GetCursorPos(&pt);                                  // 读本机光标（物理像素）
HWND hwnd = WindowFromPoint(pt);                              // 光标下窗口（可再 GetAncestor 提质）
DWORD pid = 0; GetWindowThreadProcessId(hwnd, &pid);          // PID
// PID -> 进程可执行名 / 完整路径（QueryFullProcessImageNameW），或取窗口类名 GetClassNameW
```

注意：
- 读的是**本机光标**（Deskflow 已把光标停在落点），不是 Mac 传来的坐标。
  但 `drop.x/drop.y` 可作**一致性校验**（换算后与本机光标比对，差太多就判 fail）。
- `WindowFromPoint` 会返回子控件，可用 `GetAncestor(hwnd, GA_ROOTOWNER)` 归到顶层窗口。

### 步骤 2 · 定目标（对应 `resolve_target`）

| 命中 | 计划 | 投递方式 |
|---|---|---|
| 资源管理器窗口（`explorer.exe` 且是文件夹窗口） | 该窗口**当前打开的目录** | copy 落盘；桌面命中 → 落地桌面 |
| 其它已知 App（有 PID/进程名） | 目标进程 | **剪贴板 CF_HDROP + 合成 Ctrl+V** |
| 读不到光标 / 认不出 | `%USERPROFILE%\Downloads` | copy 落盘兜底 |

资源管理器「当前目录」的取法（对应 Mac 的 `finderat.applescript`）：用 Shell COM 反查——
`Shell.Application` 的 `ShellWindows`，遍历找 `HWND` 等于命中窗口的那个，取
`Document.Folder.Self.Path`，即该窗口显示的目录。若命中窗口是桌面，则用桌面路径。

### 步骤 3 · App 投递：写剪贴板 → 激活 → 合成粘贴（对应 `apppaste.js`）

1. **写剪贴板 CF_HDROP**：`OpenClipboard` → `EmptyClipboard` → `SetClipboardData(CF_HDROP, hDrop)`
   （`DROPFILES` 结构 + 双 `\0` 结尾的宽字符串路径列表）。
   **写前/写后记账防回环**：记录 `GetClipboardSequenceNumber()`（对应 Mac 的 `changeCount`），
   让本机剪贴板守护知道「这是自己写的」→ 跳过、**不回灌 Mac**。
2. **激活目标窗口**：`SetForegroundWindow(hwnd)`（必要时 `ShowWindow(SW_RESTORE)`、
   `AttachThreadInput` 绕过前台锁），然后**轮询核对前台窗口** `GetForegroundWindow()` == 目标
   （最多约 2 s）。
3. **合成 Ctrl+V**：`SendInput` 发 `VK_CONTROL` + `'V'`（对应 Mac 的 `CGEventPost`）。
4. **绝不误粘**：前台一直不是目标窗口 → 放弃粘贴，返回 `not-frontmost`。
5. **兜底**：粘贴失败且确有源文件 → copy 落到 `Downloads`，回执标 `target.fallback`。

### 步骤 4 · 回执 sync

`{id, ts, phase(done|fail), landed, missing[], target{kind,path|app,...}, x, y}` 直推 Mac 8899。

## 暂存与清理

- 预传载荷落 `%LOCALAPPDATA%\KEEPPER\dragstage\<drag_id>\`，**半包绝不进目标目录**。
- 松手命中后才从暂存区搬到目标目录/剪贴板；暂存 TTL 与 Mac 对齐（30 s armed / 文件另设回收）。
- 同名**直接覆盖**，不生成 `(1)` 副本（与 Mac 侧一致）。

## 自测建议

1. 单测 `resolve_target` 三个分支（explorer / 其它 App / fallback），伪造光标与前台窗口，不触真实剪贴板。
2. 用记事本/写字板做「写 CF_HDROP → 激活 → Ctrl+V」的最小验证，再上微信/QQ 真机拖拽。
3. 防回环验证：App 投递期间剪贴板序号变化应被本机守护判为 self，无 payload 泄漏到 Mac。
